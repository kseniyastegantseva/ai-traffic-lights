# Approach Preview v2: схема интеграции, отказоустойчивость и статус dashboard

Статус: **проект интерфейса и исследовательская реализация в симуляторе**. Подключения к
камере, видеотрекеру или реальному контроллеру нет; пользовательский dashboard не менялся.

## Поток данных

```text
camera / tracker          estimates                controller            safety layer        plant
(кадры, track id,   ->   SensorMessage       ->   choose_phase()   ->   min/max green,  ->  SimPy
 положение, скорость)    (measurement,             (rollout либо         yellow, all-red,    либо
                          closed, heartbeat)        Detector-VA)          clearance           оборудование
```

В симуляторе слои соответствуют коду:

| Слой | Код | Что передаёт |
|---|---|---|
| Скрытая физика | `sensor.build_ground_truth` | траектории; **никогда** не уходит контроллеру |
| Измерения и ошибки | `sensor.build_feed` | сообщения с моментом выпуска `release_at` |
| Единственный вход контроллера | `CausalSensorFeed.view(now)` | смещения ETA по полосам и статус watchdog |
| Контроллер | `ControllerState.upcoming_arrival_offsets`, `preview_status` | выбор фазы |
| Безопасность и физика | `IntersectionSimulation` | жёлтый, динамический all-red, потеря времени на старт |

Сообщение `measurement` содержит ETA, вычисленное по измеренным положению и скорости на момент
кадра (`estimate_eta`: деление на `max(скорость, min_speed)`, поэтому остановившаяся машина не
даёт «мгновенного подъезда»). Сообщение `closed` — физическое событие пересечения
стоп-линии/хвоста очереди. Heartbeat подтверждает, что датчик жив.

## Отказоустойчивость (P19)

| Ситуация | Поведение в v2 | Где проверяется |
|---|---|---|
| Нет heartbeat дольше `sensor_watchdog_seconds` | `preview_status="unavailable"`, `upcoming_arrival_offsets=None` — контроллер работает как без датчика (C/A) | `test_sensor_outage_fallback_is_blind_and_safe`, серия `sweep_outage` |
| Нет измерений по треку дольше `sensor_track_timeout_seconds` | трек исчезает из вида (устаревший ETA не живёт бесконечно) | `test_eta_negative_positive_and_stale` |
| Ложные объекты и дубликаты | живут не дольше жизни объекта плюс таймаут; закрываются событием стоп-линии только настоящие | `test_duplicate_false_positive_and_missed_tracks_are_bounded` |
| Превышение бюджета вычислений | детерминированный fallback к правилу gap-out при `max_work_units` | `test_work_budget_fallback_is_deterministic_and_runtime_is_bounded` |
| Любой сбой датчика | min/max green, жёлтый, all-red принадлежат симулятору и не зависят от ETA | `test_startup_yellow_allred_zero_yellow_keep_phases_exclusive` |

Диагностика решения: `QueueBasedApproachPreviewController.last_diagnostics` хранит `decision`,
`reason`, стоимость каждого кандидата и `preview_status` последнего решения. Для реального
оборудования эти данные следует писать в журнал решений; эта запись не реализована.

## Статус dashboard (P18)

Dashboard принимает **одну фотографию**, оценивает четыре счётчика очередей и запускает
симуляцию без новых прибытий. По одному кадру нельзя определить скорость, траекторию и ETA, поэтому
режим v2 в dashboard **не реализован** и не должен выдаваться за «прогноз по камере». Любая будущая
интеграция должна явно разделять:

1. **демонстрацию по фотографии** (начальные очереди, без датчика подъезда);
2. **исследовательскую симуляцию** v2 (синтетический датчик, пресеты `camera_*`);
3. **режим реальных временных наблюдений** — только при видео или синхронных кадрах, калибровке
   геометрии, трекинге, отметках времени и проверенном fallback.

## Что необходимо для реального режима

Видеопоток или несколько синхронных кадров; калибровка камеры (пиксели → метры вдоль подъезда);
трекинг с идентификаторами; оценка скорости; схема отметок времени и задержек; калибровка
распределения ошибок ETA на отдельной выборке; проверка watchdog на живом оборудовании.
